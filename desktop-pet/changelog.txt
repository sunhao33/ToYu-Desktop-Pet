v0.65.7 (2026-10-03)
───────────────────
【用户反馈修复：数据面板 → 统计分析 → 学习统计的两幅图不显示】
  - 原因一（主因）：_on_calendar_date_selected 在「当天没有完成记录」时
    提前 return，而刷新两张图的代码在函数末尾 —— 于是图表从不刷新，
    界面上要么一直空白，要么停留在上一次选择的旧图
  - 原因二：_update_charts 在没有任务时也提前 return，只把文字设为
    「暂无数据」，既不清理上一次遗留的图，也不绘制「近 7 天」柱状图
  - 原因三：_ScaledLabel._do_scale() 在无源图时执行清图操作，而
    QLabel.setPixmap(空) 会连文本一起清空，导致刚写上的提示文字
    在随后的 resize 中被抹掉（控件尺寸一变就消失）
  - 修复：
    · 抽出 _finish_calendar_selection()，两条分支（有记录 / 无记录）
      都统一走到图表刷新
    · 无数据时也重画：环形图显示「暂无完成记录」，柱状图照常显示近 7 天趋势
    · 清图与写字分离：_clear_pixmap() 同时清文本，调用方随后 setText()；
      _do_scale() 在无源图时直接返回，不再动文本
    · 图表渲染失败时把原因直接显示在图表位置上（windowed 程序没有控制台，
      以前只 print 等于用户永远看不到），同时交给崩溃防护记入日志
  - 回归测试 _test_charts.py（12 项）：有数据/无数据日期都必须触发刷新、
    两图都要重画、切回有数据日期图要变化、渲染失败时控件上必须显示原因
    且旧图被清掉

v0.65.5 (2026-10-03)
───────────────────
【紧急修复：启动报「Error / Failed to import encodings module」】
  - 现象：双击 ToYu.exe 弹出 Error 框「Failed to start embedded python
    interpreter: Failed to import encodings module」，程序完全无法启动
  - 定位过程：对比 PyInstaller 原始产物（485 个文件，可正常运行）与解压副本
    （484 个文件，启动失败），逐个比对发现少的正是 _internal/base_library.zip；
    把该文件补回去后立刻 3/3 正常启动
  - 原因：火绒安全软件把这个内嵌 zip（里面是 Python 标准库字节码）判为威胁并
    删除，而且连打包好的 zip 里的该条目也一并清掉，所以用户拿到的包本身就是残缺的
  - 修复：两个 spec 都改为 noarchive=True，不再生成 base_library.zip，
    标准库改为散装 .pyc 落地（_internal 现在 1362 个文件、164.5 MB）。
    实测启动 6/6 正常。
  - 单文件版（onefile）确认在当前环境彻底不可用：它每次启动都要把自身解压到
    系统临时目录，火绒会把整个 _MEI 目录清掉（实测临时目录直接为空，4/4 失败）。
    因此发布包不再附带单文件版，只发布文件夹版。

【打包自检增强】
  - _package.py 每次打包后自动检查：包内是否残留 base_library.zip、
    _internal 文件数是否异常偏少，避免再次发布出残缺的包。
  - README.txt 补充杀软误删的识别方法与处理步骤（加信任区后重新解压）。

v0.65.4 (2026-10-03)
───────────────────
【修复启动时弹出「处理失败」错误框】
  - 现象：启动瞬间弹出错误框，内容类似
    「处理失败: [Errno 13] Permission denied: '...toyu_pet.png'」
  - 原因：宠物图处理是「直接覆盖原文件」。当另一个 ToYu 实例（或上一次
    运行的残留进程）正在读这张图时，Windows 会拒绝写入并抛 Errno 13。
  - 修复：改为原子写入 + 幂等写入
    · 内容与现有文件一致时直接复用，不再重写（顺带消掉启动时的多余写盘）
    · 需要写入时先写 .tmp 再 os.replace 原子替换，中途失败不会损坏图片
    · 被占用时自动重试一次；仍失败则给出人话提示
      「宠物图片被占用，请关闭其他 ToYu 窗口或正在查看该图片的程序后重试」
    · 不再残留临时文件
  - 新增回归测试 _test_image_save.py（11 项）：含幂等性、内容变更必须生效、
    他方持有句柄时仍可写入、6 线程并发写入不损坏文件、无临时文件残留。

【说明】本轮还排查并确认了两件与代码无关的环境现象：
  - 单文件版 exe 被杀软拦截解压导致的「could not create temporary directory」
  - 离屏测试环境下 Qt 退出阶段的段错误会污染测试退出码（已用 os._exit 规避），
    真实窗口模式完整退出流程经验证返回码为 0

v0.65.3 (2026-10-03)
───────────────────
【紧急修复：点击顶部标签后无法切换到其他页面】
  - 原因：v0.65.1 修内存泄漏时把「切换页面的淡入动画」改成复用同一个
    QGraphicsOpacityEffect 对象，而切换结束回调里执行了
    setGraphicsEffect(None) —— Qt 会因此把这个效果对象删除。
    第二次点击标签时 setGraphicsEffect(已删除的对象) 抛
    RuntimeError，异常在建栈过程中抛出，后面的
    _page_stack.setCurrentIndex() 根本没执行，页面就切不过去了。
  - 修复：改为每个页面各自持有一个常驻的透明度效果对象，动画重复使用；
    切换结束只把不透明度恢复为 1.0，不再删除对象。
  - 加固：额外挂一个 400ms 兜底定时器，即使动画被打断也能恢复不透明度，
    避免页面停留在完全透明的状态。
  - 新增回归测试 _test_tab_switch.py（8 项）：三轮点击全部 4 个标签、
    校验页面索引、不透明度恢复、标签互斥、工具页子标签顺序、快速连点。

【测试基建修复】
  - 之前测试脚本用 sys.exit() 退出时，Qt 在离屏模式下回收窗口会触发段错误，
    把退出码污染成崩溃码，导致「全部通过」的测试被误判为失败。
    已统一改为打印完结果后 os._exit()，退出码不再被污染。
  - 已验证真实窗口模式下的完整退出流程返回码为 0、stderr 干净。

v0.65.1 (2026-10-03)
───────────────────
【稳定性修复 · 长时间运行崩溃】
  - 崩溃根因：PyQt6 中槽函数/回调里未捕获的异常会直接 abort 整个进程，
    windowed exe 没有控制台，所以表现为「跑一段时间软件突然消失、无任何报错」
  - 新增全局崩溃防护（main.py）：
    · 未捕获异常不再终止进程，程序继续运行
    · 完整 traceback 自动写入 %APPDATA%\ToYu\errors.log（超过 512 KB 自动轮转）
    · 桌面上弹出「⚠️ 出了点小问题，已自动恢复」气泡，不再静默消失
  - 修复内存泄漏（长时间运行后内存持续上涨的元凶）：
    · pet_bubble.py CompanionBubble._bounce_in 每次弹气泡都新建 QPropertyAnimation
      且旧对象永不释放 → 实测每帧泄漏 1 个，4 分钟堆积 15,266 个
    · ui/main_window.py 每次切换标签页都新建 QPropertyAnimation + QGraphicsOpacityEffect
      挂在主窗口下 → 改为复用同一对对象
    · pet_food.py 食物弹跳动画无父对象 → 补父对象 + DeleteWhenStopped
    · 修复后实测：4 分钟 RSS 增长从 +30.1 MB 降到 +1.2 MB，
      Python 对象增长从 +78,327 降到 +1,905，QPropertyAnimation 归零
  - 修复精灵可见区域检测（pet_engine/sprite_bounds.py）：
    · QImage.constScan 在 PyQt6 中不存在，一旦调用必抛 AttributeError
      （该路径此前只在异常分支被触发，属于潜伏崩溃点）
    · numpy 直接引用临时 QImage 缓冲区导致野指针，大图会出现 access violation
      （实测 512×512 崩溃，已改为拷贝出 alpha 通道，13/13 回归测试通过）
    · 顺手把逐像素 pixelColor 扫描（O(w×h) 次 Python 调用）改为 numpy 向量化，
      512×512 从卡顿降到 0.63 ms/次
  - 精灵可见区域现在在加载宠物图后立即计算，配件/气泡据此对齐真实内容
  - 新增浸泡测试脚本 _soak.py：可指定分钟数，持续驱动游戏循环、交互、
    配件、粒子、气泡与桌面工具，逐分钟输出内存/线程/对象数时间线
  - 新增回归测试：_test_sprite_bounds.py（13 项）、_test_crash_guard.py、
    _test_tools.py（26 项），可用 _test_all.py 一键全跑
