  - 深色模式联动：心流窗口的深色开关直接操作主窗口的深浅色设置，两边同步
  - 模式持久化保持不变：停在心流窗口退出，下次启动自动进入心流窗口
  - 关掉心流窗口等价于"回到 ToYu"，不会让程序变成没有窗口可用

v0.65.12 (2026-10-03)
────────────────────
【用户反馈修复：AI 栏底部内容被裁、倒计时器在最小尺寸下显示不全】
  - 真正原因不是宽度而是**高度**：AI 页内容约 800 高（AI 伴侣 + API 配置 +
    性格设置 + 保存按钮），而窗口最小高度被设为 700 —— 内容区只有 490 高，
    底部内容被直接裁掉（AI 页没有纵向滚动区，超出的部分无法到达）
  - 上一版只让宽度自适应，高度仍是写死的 700，所以缩到最小尺寸后
    AI 栏底部依旧看不见
  - 修复：最小尺寸改为**宽高都按内容自适应**
    · 高度用 sizeHint()（内容自然高度）而不是 minimumSizeHint()
      —— 后者对普通容器往往返回很小的值（AI 页只报 654，实际需要 800）
    · 起始尺寸与最小尺寸固化为具名常量：MIN_SIZE=(980,850)、START_SIZE=(1120,880)
    · 实测各页需求：宠物页 838×791、效率工具/数据面板 838×827、AI 页 962×844
  - 验证（真实窗口渲染截图确认）：
    · 最小尺寸 980×850 下 AI 页「保存 AI 设置」按钮完整可见
    · 同一尺寸下倒计时器大字时间 `00:00:00` 完整显示
    · 缩到最小尺寸后四个页面 + 三个子页横向溢出全部为 0
  - 回归测试 _test_window_resize.py 扩充到 8 项（新增最小高度、起始尺寸校验）

v0.65.9 (2026-10-03)
───────────────────
【修复：换宠物图/改缩放后，宠物跑到屏幕外（看起来像"消失"）】
  - 现象：重启后桌面上找不到宠物；实测宠物窗口位于 (-57, 1216)，
    而屏幕高 1440、窗口高 239，可见底边算出来 1455 —— 整个宠物被压到
    屏幕底部之外，只在左下角露出一角
  - 原因：_clamp_to_screen() 的 y 上限依赖 _sprite_bottom_offset 与当前窗口高度，
    而 _restore_position() 是在窗口还没按图片尺寸调整、_sprite_bottom_offset
    仍为 0 时做的钳制；之后 set_pet_image() / set_scale() 把窗口变大，
    却再也没重新钳制，于是原本"合法"的坐标把宠物顶出了屏幕
  - 修复：
    · _update_window_size() 结束时重新执行 _clamp_to_screen()
    · _restore_position() 钳制后立刻把最终位置写回设置，避免出现
      "界面上在屏幕内、存档里却仍是屏幕外坐标"的不一致
  - 回归测试 _test_pet_onscreen.py（5 项）：从屏幕外位置恢复、换更大宠物图、
    放大到 1.8 倍三种情况下宠物可见底边都必须落在屏幕工作区内；
    合法位置不被误改；钳制结果会写回设置

【记录一个测试自身的坑】
  - 该测试最初用写死的任务栏高度(48)算参照，而离屏测试环境下检测不到任务栏
    （高度 0），导致断言算错、把正确的实现判成失败。现已改为从宠物实例读取
    真实任务栏高度。教训：断言里的参照值必须与产品取同一来源。

【修复：换宠物后配件（帽子/雨伞/皇冠等）位置会歪】

    不再依赖添加配件这条路径
  - 实测：默认土豆图比例 left=0.05/right=0.05，换成 TV 小电视后为
    left=0.09375/right=0.125，修复后配件层能正确跟随

v0.65.7 (2026-10-03)

【用户反馈修复：数据面板 → 统计分析 → 学习统计的两幅图不显示】
  - 原因一（主因）：_on_calendar_date_selected 在「当天没有完成记录」时

    · 无数据时也重画：环形图显示「暂无完成记录」，柱状图照常显示近 7 天趋势
    · 清图与写字分离：_clear_pixmap() 同时清文本，调用方随后 setText()；
      _do_scale() 在无源图时直接返回，不再动文本
    · 图表渲染失败时把原因直接显示在图表位置上（windowed 程序没有控制台，
      以前只 print 等于用户永远看不到），同时交给崩溃防护记入日志
  - 回归测试 _test_charts.py（12 项）：有数据/无数据日期都必须触发刷新、
    两图都要重画、切回有数据日期图要变化、渲染失败时控件上必须显示原因
    且旧图被清掉

v0.65.5 (2026-10-03)

【紧急修复：启动报「Error / Failed to import encodings module」】
  - 现象：双击 ToYu.exe 弹出 Error 框「Failed to start embedded python
    interpreter: Failed to import encodings module」，程序完全无法启动
  - 定位过程：对比 PyInstaller 原始产物（485 个文件，可正常运行）与解压副本
    （484 个文件，启动失败），逐个比对发现少的正是 _internal/base_library.zip；
    把该文件补回去后立刻 3/3 正常启动
  - 原因：火绒安全软件把这个内嵌 zip（里面是 Python 标准库字节码）判为威胁并
    删除，而且连打包好的 zip 里的该条目也一并清掉，所以用户拿到的包本身就是残缺的
  - 修复：两个 spec 都改为 noarchive=True，不再生成 base_library.zip，
    标准库改为散装 .pyc 落地（_internal 现在 1362 个文件、164.5 MB）。
    实测启动 6/6 正常。
  - 单文件版（onefile）确认在当前环境彻底不可用：它每次启动都要把自身解压到
    系统临时目录，火绒会把整个 _MEI 目录清掉（实测临时目录直接为空，4/4 失败）。
    因此发布包不再附带单文件版，只发布文件夹版。

【打包自检增强】
  - _package.py 每次打包后自动检查：包内是否残留 base_library.zip、
    _internal 文件数是否异常偏少，避免再次发布出残缺的包。
  - README.txt 补充杀软误删的识别方法与处理步骤（加信任区后重新解压）。
